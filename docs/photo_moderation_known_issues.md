# Известные проблемы photo moderation

Документ фиксирует наблюдаемые проблемы для отдельной последующей задачи. В рамках текущего промежуточного изменения они не исправляются.

## 1. Удаление последнего проблемного фото не восстанавливает видимость

Если фото было отклонено модерацией и профиль получил состояние `UNDER_REVIEW`/`moderation_locked`, пользователь может удалить это фото. После удаления профиль остаётся скрытым, даже если проблемное фото больше не входит в анкету.

Ожидаемое поведение: после удаления отклонённого фото профиль должен снова стать видимым, если нет другого активного moderation case, санкции или других причин для блокировки.

Текущее наблюдаемое поведение: видимость восстанавливается только после добавления следующего фото, которое проходит проверку. Нужно отдельно определить корректное поведение для пустого профиля и профиля с оставшимися валидными фотографиями.

## 2. Replacement может считать старое фото при обновлении состава анкеты

При сценарии замены фото наблюдается рассинхронизация между фактическим числом фотографий и отображаемым/используемым количеством: после замены новая фотография может выглядеть как дополнительная, а одна фотография учитывается дважды. В результате анкета с тремя фотографиями может вести себя так, будто в ней уже четыре или что новая фотография была добавлена вместо ожидаемой замены.

Нужно отдельно проверить:

- порядок `old_file_id`/`new_file_id` в `replace_photo`;
- синхронизацию `photo_file_ids`, `extra_data.photo_file_ids`, `photo_file_id` и `main_photo_file_id`;
- повторную обработку callback/state после неуспешной проверки;
- очистку старого moderation case и старого cache после удаления/замены;
- отображение количества фотографий после успешной и отклонённой замены.

Ожидаемое поведение: replacement атомарно заменяет один старый ID одним новым ID, не увеличивает количество фотографий и не оставляет старый ID в активном составе анкеты.

## Ограничения текущей записи

Эти наблюдения требуют отдельного воспроизведения на реальном пользовательском сценарии с логами `photo_file_id`, списком `photo_file_ids`, `extra_data` и состояниями профиля до/после операции. Не следует исправлять их только по тексту уведомления или по одному moderation case.
